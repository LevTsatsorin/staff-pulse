# mock-api Specification

## Purpose
Mock-сервер, имитирующий backend орг-структуры: отдаёт снапшот дерева (позже — поток изменений и AI-парсинг запросов), чтобы клиент можно было разрабатывать и демонстрировать без реального API.

## Requirements

### Requirement: Снапшот орг-структуры
Сервер ДОЛЖЕН отдавать `GET /api/org-tree` как JSON-массив узлов `{ id, name, parentId, headcount, budget, performance, updatedAt }`: у корня `parentId` равен `null`, `performance` в диапазоне 0–100, `updatedAt` — ISO-строка, `headcount` есть у каждого узла, а не только у листьев.

#### Scenario: Успешный ответ
- **WHEN** клиент запрашивает `GET /api/org-tree`
- **THEN** ответ 200 с `Content-Type: application/json` и массивом не менее 40 узлов с не менее чем тремя уровнями вложенности

#### Scenario: Детерминированные данные
- **WHEN** сервер перезапущен
- **THEN** набор узлов (id, названия, структура) совпадает с предыдущим запуском

### Requirement: Условные запросы
Сервер ДОЛЖЕН отдавать `ETag`, равный текущей версии данных, и `Cache-Control: no-cache`; при совпадении `If-None-Match` отвечать 304 без тела.

#### Scenario: Данные не менялись
- **WHEN** клиент повторяет запрос с `If-None-Match`, равным текущему `ETag`
- **THEN** ответ 304 без тела

#### Scenario: Данные изменились
- **WHEN** версия данных выросла после предыдущего ответа
- **THEN** ответ 200 с новым `ETag`

### Requirement: Демонстрационные сценарии
Сервер ДОЛЖЕН поддерживать переменную окружения `MOCK_SCENARIO` для воспроизведения состояний клиента: `empty` — пустой массив, `error` — ответ 500, `slow` — задержка не менее 2 с, `invalid` — тело, не проходящее схему.

#### Scenario: Пустой ответ
- **WHEN** сервер запущен с `MOCK_SCENARIO=empty`
- **THEN** `GET /api/org-tree` отвечает 200 с `[]`

#### Scenario: Ошибка сервера
- **WHEN** сервер запущен с `MOCK_SCENARIO=error`
- **THEN** `GET /api/org-tree` отвечает 500 с JSON `{ "message": "..." }`

#### Scenario: Невалидное тело
- **WHEN** сервер запущен с `MOCK_SCENARIO=invalid`
- **THEN** ответ 200 содержит узел без обязательного поля

### Requirement: Неизвестные маршруты
Сервер ДОЛЖЕН отвечать 404 с JSON-телом на неизвестные пути под `/api`.

#### Scenario: Неизвестный путь
- **WHEN** запрос `GET /api/unknown`
- **THEN** ответ 404 с JSON `{ "message": "Not found" }`

### Requirement: Поток изменений
Сервер ДОЛЖЕН принимать WebSocket-соединения на `/ws`, отправлять `hello` с текущей версией и рассылать патчи всем подключённым клиентам. Тикер меняет случайный узел каждые 1–3 с (интервал настраивается через `PATCH_INTERVAL_MS`), периодически — пачку из 2–4 узлов. Каждый патч увеличивает версию, которая совпадает с `ETag` снапшота.

#### Scenario: Подключение
- **WHEN** клиент открыл `/ws`
- **THEN** первым сообщением получает `hello` с версией, равной `ETag` текущего снапшота

#### Scenario: Рассылка
- **WHEN** тикер изменил узел
- **THEN** все подключённые клиенты получают одинаковый `patch`, а последующий `GET /api/org-tree` отдаёт обновлённые значения и новый `ETag`

#### Scenario: Сценарии без патчей
- **WHEN** сервер запущен с `MOCK_SCENARIO=empty`, `error` или `invalid`
- **THEN** тикер не запускается, `hello` по-прежнему отправляется
