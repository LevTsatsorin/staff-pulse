# ai-search Specification

## Purpose
Поиск на естественном языке: запрос пользователя превращается в структурированный фильтр таблицы, а при недоступности AI работает обычный текстовый поиск.

## Requirements

### Requirement: Разбор запроса
Сервер ДОЛЖЕН принимать `POST /api/search/parse` с `{ "query": string }` и возвращать структурированный фильтр `{ text, levels, headcount: { min, max }, budget: { min, max }, performance: { min, max }, sort: { key, direction } }`, полученный от языковой модели со structured output; неупомянутое условие или граница — `null`, границы включительны. Ключ модели хранится только на сервере.

#### Scenario: Числовое условие
- **WHEN** запрос «команды с эффективностью ниже 50»
- **THEN** ответ содержит `levels: [3]` и `performance: { max: 50 }`

#### Scenario: Свободный текст
- **WHEN** запрос «продажи»
- **THEN** ответ содержит `text: "продажи"` без числовых условий

### Requirement: Применение на клиенте
Клиент ДОЛЖЕН валидировать ответ схемой, показывать распознанные условия чипами с возможностью удалить каждое и применять фильтр к строкам таблицы поверх обычного пайплайна; агрегаты не пересчитываются.

#### Scenario: Чипы
- **WHEN** фильтр распознан как `levels: [3]` + `performance: { max: 50 }`
- **THEN** показаны чипы «Уровень: команда» и «Эффективность ≤ 50», удаление чипа снимает условие

### Requirement: Fallback
При отсутствии ключа, ошибке, таймауте (5 с) или невалидном ответе клиент ДОЛЖЕН молча перейти к текстовому поиску по названию и показать бейдж «AI недоступен»; ввод при этом не блокируется.

#### Scenario: Без ключа
- **WHEN** сервер запущен без `OPENAI_API_KEY`
- **THEN** `POST /api/search/parse` отвечает 503, клиент фильтрует по тексту, виден бейдж «AI недоступен»

#### Scenario: Таймаут
- **WHEN** модель не ответила за 5 с
- **THEN** запрос прерван, применён текстовый поиск
