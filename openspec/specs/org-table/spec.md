# org-table Specification

## Purpose
Аналитическая таблица подразделений с агрегированными показателями по поддереву, сортировкой, фильтром и связью с деревом.

## Requirements

### Requirement: Столбцы и агрегаты
Таблица ДОЛЖНА показывать по одной строке на каждый узел со столбцами: Подразделение (название и путь родителей мелким текстом), Уровень (число и метка Дивизион / Отдел / Команда), Всего сотрудников, Бюджет суммарный, Средняя эффективность. Суммарные показатели включают узел и всех его потомков; средняя эффективность взвешена по `headcount`.

#### Scenario: Агрегат по поддереву
- **WHEN** у отдела собственный headcount 5 и две команды по 10 с performance 60 и 80, собственная performance 100
- **THEN** строка отдела показывает 25 сотрудников и среднюю эффективность (100·5 + 60·10 + 80·10) / 25 = 76

#### Scenario: Нулевой суммарный headcount
- **WHEN** у узла и всех потомков headcount 0
- **THEN** средняя эффективность отображается как «—»

#### Scenario: Формат бюджета
- **WHEN** суммарный бюджет узла равен 12345678
- **THEN** ячейка содержит «12 345 678 руб.» с неразрывными пробелами между группами

### Requirement: Сортировка
Клик по заголовку другого столбца ДОЛЖЕН включать сортировку по нему по возрастанию, одинаково для текстовых и числовых столбцов; клик по активному столбцу ничего не меняет; двойной клик ДОЛЖЕН обращать направление. С клавиатуры Enter или Space на активном заголовке обращает направление. Заголовок несёт `aria-sort`.

#### Scenario: Смена столбца
- **WHEN** активна сортировка по названию и пользователь кликает «Бюджет суммарный»
- **THEN** строки упорядочены по бюджету по возрастанию, `aria-sort="ascending"` у этого заголовка, у заголовка названия `aria-sort="none"`

#### Scenario: Двойной клик
- **WHEN** пользователь дважды кликает по активному заголовку
- **THEN** направление меняется на противоположное ровно один раз, текст заголовка не выделяется

#### Scenario: Двойной клик по неактивному столбцу
- **WHEN** активна сортировка по уровню, и пользователь дважды кликает по «Подразделение» или по «Средняя эффективность»
- **THEN** в обоих случаях строки упорядочены по этому столбцу по убыванию

#### Scenario: Пустые значения при сортировке
- **WHEN** сортировка по средней эффективности в любом направлении
- **THEN** строки со значением «—» находятся в конце

### Requirement: Фильтр по названию
Поле фильтра ДОЛЖНО быть управляемым и применяться в реальном времени с дебаунсом 250 мс, без учёта регистра (`ru`); совпадение подсвечивается; агрегаты от фильтра не зависят; показан счётчик «N из M».

#### Scenario: Ввод текста
- **WHEN** пользователь вводит «прод» и перестаёт печатать
- **THEN** не позднее чем через ~250 мс остаются только строки, чьё название содержит «прод» без учёта регистра, совпавший фрагмент подсвечен

#### Scenario: Ничего не найдено
- **WHEN** фильтру не соответствует ни одна строка
- **THEN** показано состояние «Ничего не найдено» с кнопкой «Сбросить фильтр», которая очищает поле

#### Scenario: Агрегаты неизменны
- **WHEN** фильтр скрыл часть команд отдела
- **THEN** строка отдела показывает те же суммарные значения, что и без фильтра

### Requirement: Связь с деревом
Клик по строке ДОЛЖЕН выделять узел в дереве: выделенная строка подсвечена, предки узла раскрыты, узел прокручен в видимую область.

#### Scenario: Выбор строки
- **WHEN** пользователь кликает по строке команды, чей отдел свёрнут
- **THEN** отдел раскрывается, узел команды выделен и виден, строка таблицы подсвечена

### Requirement: Мемоизация
Агрегаты ДОЛЖНЫ вычисляться один раз после загрузки данных; сортировка и фильтр не пересчитывают агрегаты, а только переупорядочивают и отбирают готовые строки.

#### Scenario: Сортировка после загрузки
- **WHEN** пользователь меняет сортировку или фильтр
- **THEN** функция агрегации не вызывается повторно (проверяется по счётчику вызовов в тесте или профайлере)
