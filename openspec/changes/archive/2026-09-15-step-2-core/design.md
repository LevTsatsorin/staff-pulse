## Context

Модель из этапа 01 лежит в кэше TanStack Query. Требования 02: агрегаты «считаются один раз и мемоизируются», сортировка кликом / обратная двойным, дебаунс 250 мс, формат `12 345 678 руб.`, связь строка ↔ узел. Этап 03 потребует инкрементального пересчёта, поэтому структура агрегатов выбирается уже сейчас.

## Goals / Non-Goals

**Goals:** агрегаты в модели, таблица как настоящий `<table>`, чистые функции сортировки/фильтра с тестами, двусторонняя связь с деревом.

**Non-Goals:** keyboard navigation, fade обновлённых ячеек, виртуализация (52 строки).

## Decisions

- **Агрегаты — часть `OrgModel`, считаются в `buildOrgModel` (реализовано на этапе 01, см. ADR-002).** `aggregates[id] = { totalHeadcount, totalBudget, perfWeightedSum, avgPerformance }`; `avgPerformance = perfWeightedSum / totalHeadcount` или `null`. Хранить `perfWeightedSum` отдельно нужно, чтобы на 03 пересчитывать предка из прямых детей без повторного обхода поддерева. Альтернатива — `useMemo` от сырого массива — пересчитывает всё при каждом патче. → ADR-002.
- **Пайплайн строк — цепочка чистых функций** `toTableRows(model)` → `filterRows(rows, query)` → `sortRows(rows, sort)`, каждая в своём `useMemo` внутри `useTableRows`. `toTableRows` зависит только от модели, поэтому фильтр и сортировка её не трогают.
- **Сортировка:** чистая `getNextSort(prev, key, trigger)`; `useSortState` — тонкая обёртка с локальным состоянием `SortState | null`. По умолчанию `null` — порядок дерева. Клик по новому столбцу всегда включает возрастание. Разные стартовые направления для текста и чисел отклонены после проверки автором: переключение столбцов и двойной клик по неактивному столбцу давали разный результат в зависимости от типа столбца. Компаратор на столбец через `Record<SortKey, …>`; `null` всегда в конце; строки — `Intl.Collator('ru-RU')` один раз на модуль; равенство — по порядку дерева. `click` по активному столбцу идемпотентен, `dblclick` переключает, потому что `dblclick` всегда приходит после двух `click`. Клавиатурная активация кнопки даёт `click` с `event.detail === 0` и трактуется как `reverse`.
- **Фильтр:** `useDebouncedValue(query, SEARCH_DEBOUNCE_MS)`; очистка применяется без дебаунса; сравнение через `toLocaleLowerCase('ru-RU')`; подсветка `<mark>` через `splitByMatch` (сегменты с `start` — стабильный ключ).
- **Формат денег:** `Intl.NumberFormat('ru-RU')` создаётся один раз на модуль; тест проверяет U+00A0 как разделитель групп.
- **`SelectionProvider`** держит `selectedId` и `expandedIds` (Set) — оба переживают патчи, фильтр и переключение представлений. Данных в контексте нет: единственный источник — кэш. `useRevealNode(model)` = выбрать + раскрыть предков; прокрутка — эффект внутри `OrgTreeNode` по `isSelected`.
- **Раскладка — только CSS.** `SplitView` всегда рендерит обе панели; медиазапрос `width < 1280px` скрывает неактивную по `data-view`, переключатель скрыт от 1280px. Вариант с `useMediaQuery` отклонён: JS-подписка на размер окна не нужна, если решение принимает CSS, а обе панели и так остаются смонтированными.
- **Строки таблицы — `React.memo(OrgTableRow)`** с пропсами `row`, `isSelected`, `query`, `onSelect`. Пока `toTableRows` пересоздаёт все строки на каждую новую модель, memo помогает только при смене выделения; переиспользование неизменённых строк — задача этапа 03.

## Risks / Trade-offs

- [Путь родителей в ячейке названия делает строку высокой] → две строки текста, `line-height` компактный; на узких экранах путь скрывается.
- [`dblclick` недоступен с клавиатуры] → Enter/Space на активном заголовке обращает направление, описано в README.
- [`localeCompare` медленный на больших данных] → 52 строки; при росте — `Intl.Collator` один раз на модуль.
