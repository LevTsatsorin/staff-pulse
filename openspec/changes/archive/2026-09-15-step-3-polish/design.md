## Context

Модель с агрегатами лежит в кэше (этапы 01–02). Нужны: транспорт изменений, применение патчей без рефетча, устойчивый реконнект, UX-доводка. В ТЗ прямо назван «контракт WebSocket-патча», выбор транспорта фактически подсказан.

## Goals / Non-Goals

**Goals:** WS-поток с версионированием, инкрементальный `applyPatch` с тестом эквивалентности, backoff, индикатор, fade, keyboard nav, анимация дерева.

**Non-Goals:** изменение `parentId`/`name` патчем, гарантированная доставка (при обрыве — один рефетч), keyboard nav по дереву (опционально, если останется время).

## Decisions

- **WebSocket, не SSE и не поллинг.** Документы ТЗ требуют контракт WS-патча; SSE проще, но потребует объяснять отклонение; поллинг противоречит «без лишних запросов». → ADR-003.
- **Версионирование.** Сервер держит `version`, растущую на 1 с каждым патчем; она же — `ETag` снапшота. Решения — в чистой `resolveLiveMessage`: `version <= model.version` → игнор; `=== +1` → `setQueryData(applyPatch)`; пропуск или неизвестный `id` → `invalidateQueries` с `cancelRefetch: false`. `hello` с версией, отличной от модели в любую сторону, → рефетч, при совпадении — ничего. Так пропуски во время обрыва и перезапуск сервера (`node --watch` сбрасывает версию на 1) закрываются одним снапшотом, а переподключение без изменений не стоит запроса. → ADR-003.
- **`applyPatch(model, changes)`** — чистая функция: копирует затронутые узлы, поднимается по `parentId`, пересчитывает агрегат каждого предка из прямых детей (не дельтой — float уплывает). Новые объекты только для узла и цепочки предков; `nodes`/`aggregates` копируются одним spread на патч, а не на изменение. Тест: 1000 случайных патчей ≡ `buildOrgModel` от итоговых узлов.
- **Подписка — `useOrgLiveUpdates(queryClient)`** в `DashboardPage`, один эффект: сокет, таймер, флаг `disposed` в cleanup (StrictMode монтирует дважды). Backoff `min(30_000, 1_000 · 2^attempt) · (0.5 + random/2)`, `attempt = 0` на `open`, слушатель `online`. Возвращает `{ status, nextRetryAt }` для бейджа; провайдер не нужен — статус нужен только шапке.
- **Fade без таймеров и без версии снапшота.** `FlashValue` хранит `{ value, generation }` и при реальном изменении значения увеличивает поколение прямо во время рендера; поколение — `key` внутреннего `<span>`, поэтому перемонтируются и мигают только изменённые ячейки. Первые монтирования (загрузка, раскрытие, фильтр) остаются на поколении 0. Изначальный план — включать анимацию при `version !== snapshotVersion` — отклонён при реализации: в момент первого патча анимация стартовала бы у всех уже отрисованных ячеек; поле `snapshotVersion` удалено из модели. При reduced motion подсветка держится 1.5 с через `steps(1, end)`.
- **Стабильные перерисовки.** Строки пересобираются на каждую модель, поэтому `OrgTableRow` сравнивает поля строки (`isSameRow`) в компараторе `memo`, а `useRevealNode` читает модель из ref и отдаёт стабильный колбэк (patch не меняет `parentId`).
- **Keyboard nav — `useRovingRows(rowIds)`**: `activeId` по id, обработчик `onKeyDown` на `<tbody>`, `tabIndex` 0 только у активной строки, фокус ставится эффектом при изменении `activeId` от клавиатуры (флаг в ref, чтобы не фокусировать при монтировании). Исчезновение `activeId` из `rowIds` → первая строка.
- **Анимация высоты — CSS grid.** Обёртка `display: grid; grid-template-rows: 0fr | 1fr; transition: grid-template-rows 200ms`, внутри `overflow: hidden; min-height: 0`; свёрнутому содержимому `inert`. Переключается только transient-проп → класс, никакого `style`. `interpolate-size: allow-keywords` не используется (поддержка только Chromium). Глобально `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation: none; transition: none } }`. → ADR-004. Дети ветки всегда смонтированы; прокрутка к узлу, выбранному из таблицы, откладывается на длительность анимации (`EXPAND_ANIMATION_MS`), иначе измерялась бы ещё свёрнутая ветка.
- **Сервер:** `ws` на том же `http.Server` (`server.on('upgrade')` с проверкой пути `/ws`); тикер — `setTimeout` с случайным интервалом, каждый ~5-й тик пачка 2–4 узлов; изменения ограничены `headcount`/`budget`/`performance`, диапазоны сохраняются (0–100).

## Risks / Trade-offs

- [Патч сдвигает активную/выделенную строку при сортировке по изменяемому столбцу] → фокус и выделение по id, строка «уезжает», но фокус остаётся на ней.
- [Много патчей → частые перерисовки] → `React.memo` строк + сохранение ссылок в `applyPatch`; интервал 1–3 с далёк от предела.
- [Потеря патчей при обрыве] → один рефетч снапшота после `open`; принято сознательно, без буферизации на сервере.
- [`inert` в старых браузерах] → baseline с 2023, для тестового достаточно.
