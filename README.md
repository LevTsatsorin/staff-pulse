# Staff Pulse

Дашборд для мониторинга орг-структуры компании: дивизионы → отделы → команды. Интерактивное дерево и аналитическая таблица с агрегированными показателями, live-обновления по WebSocket.

Тестовое задание. Этапы реализуются по очереди, каждый — отдельный коммит с тегом `step/N`.

| Этап | Тег | Статус |
|---|---|---|
| 01 Foundation — каркас, mock API, дерево | `step/1` | ✅ |
| 02 Core — аналитическая таблица | `step/2` | ⏳ |
| 03 Polish — live-обновления, клавиатура, анимации | `step/3` | ⏳ |
| 04 Bonus — Docker, nginx, AI-поиск | `step/4` | ⏳ |

## Запуск

```bash
pnpm install
pnpm dev
```

Клиент: http://localhost:5173, mock API: http://localhost:3001. Требуется Node ≥ 24 (сервер исполняет TypeScript напрямую, без транспиляции).

Переменные окружения сервера описаны в `.env.example`; файл `.env` необязателен (`cp .env.example .env`), сервер подхватывает его через `node --env-file-if-exists`.

Скрипты: `dev` (клиент + сервер), `build`, `start` (превью прод-сборки), `typecheck`, `test`, `lint`, `lint:fix`.

### Состояния клиента

Mock-сервер воспроизводит состояния через переменную окружения:

```bash
MOCK_SCENARIO=empty pnpm dev:server    # пустой ответ
MOCK_SCENARIO=error pnpm dev:server    # 500
MOCK_SCENARIO=slow pnpm dev:server     # задержка 2 с (skeleton)
MOCK_SCENARIO=invalid pnpm dev:server  # ответ, не проходящий схему
```

## Стек

React 19, Vite, TypeScript (strict), styled-components, TanStack Query, zod, Biome, Vitest. Mock-сервер — `node:http`, без фреймворков.

## Структура репозитория

```
src/        клиент: api/ components/ hooks/ pages/ utils/ types/ constants/ styles/
server/     mock API (Node 24, .ts без сборки)
shared/     контракт, общий для клиента и сервера: zod-схемы, пути API
docs/       architecture.md, data-model.md, adr/
openspec/   спецификации и планы по этапам (spec-driven workflow)
```

## Интерпретации ТЗ

Места, где ТЗ допускает несколько прочтений, и выбранный вариант:

- **«Второй уровень открыт по умолчанию»** — раскрыты корневые узлы: видны дивизионы и их отделы, команды свёрнуты. Глубина задаётся константой `DEFAULT_EXPANDED_DEPTH`.
- **`headcount` и `performance` в узле дерева** — суммарная численность поддерева и средняя эффективность, взвешенная по численности: иерархию читают сверху вниз как суммы. Собственные значения узла — в подсказке при наведении.
- **Слой кэширования** — TanStack Query, а не собственный кэш: ТЗ допускает «аналог», см. [ADR-001](docs/adr/001-tanstack-query-cache.md).
- Остальные интерпретации (сортировка двойным кликом, фильтр и агрегаты, контракт патча) появятся вместе с соответствующими этапами.

## AI в разработке

Раздел заполняется по ходу работы и будет завершён на последнем этапе. Кратко: планирование и спецификации (`openspec/`), конвенции кода и решения (`.claude/skills/`) ведутся вместе с Claude Code; что генерировалось, что переписывалось руками и почему — фиксируется по каждому этапу.
