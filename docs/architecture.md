# Архитектура

Документ обновляется по этапам. Актуален для этапа 03; раздел этапа 04 помечен.

## Слои

```
┌──────────────────────────────────────────────────────┐
│ pages/            DashboardPage — только композиция   │
├──────────────────────────────────────────────────────┤
│ components/       common/ (состояния, индикаторы)     │
│                   layout/ (шапка, split-view, панели) │
│                   orgTree/ (дерево)  orgTable/        │
├──────────────────────────────────────────────────────┤
│ hooks/            useOrgTree, useOrgLiveUpdates, …    │
│ providers/        SelectionProvider — UI-состояние    │
├──────────────────────────────────────────────────────┤
│ api/              fetchJson → getOrgTree → queryClient│
│ utils/            чистые функции + тесты              │
├──────────────────────────────────────────────────────┤
│ shared/           zod-схемы и пути API (клиент+сервер)│
└──────────────────────────────────────────────────────┘
```

Правило: логика в хуках и утилитах, разметка в компонентах, страница только собирает. Компоненты не знают про транспорт; хуки не знают про разметку.

## Поток данных: от API до UI

1. `useOrgTree` вызывает `useQuery` с ключом `['org-tree']`. TanStack Query передаёт `AbortSignal`: при размонтировании последнего потребителя незавершённый запрос отменяется.
2. `getOrgTree(signal)` → `fetchJson` (`fetch` с `Accept: application/json`, HTTP-ошибка → `ApiError`).
3. Ответ проверяется схемой `orgTreeResponseSchema` (zod). Невалидный ответ → `ApiValidationError`.
4. `buildOrgModel` нормализует массив в `OrgModel`: `nodes` по id, `childrenIds`, `rootIds`, глубина, и один раз считает агрегаты поддерева (`aggregate.ts`: суммарные численность и бюджет, средняя эффективность, взвешенная по численности). Дубли id, сироты и циклы → `OrgDataError`.
5. В кэше лежит готовая модель, а не сырой массив. Версия снапшота берётся из `ETag`.
6. `DashboardPage` ветвится по наличию данных: нет данных и `pending` → skeleton в обеих панелях; нет данных и ошибка → `ErrorState` с «Повторить»; пустой `rootIds` → `EmptyState`; иначе дерево и таблица внутри `SelectionProvider`. Если данные уже есть, а фоновый запрос упал, данные остаются, шапка пишет «не удалось обновить».

Кэш: `staleTime: 5 000 мс`. Повторное использование данных в пределах 5 с не создаёт запроса; после — фоновая ревалидация, старые данные остаются на экране, в шапке индикатор «обновляется…». `structuralSharing` сохраняет ссылки, если данные не изменились, поэтому потребители не перерисовываются.

Сообщения об ошибках для пользователя собирает одна функция `toUserMessage(error)`.

## Выделение и раскрытие

Данные живут только в кэше. `SelectionProvider` хранит UI-состояние, общее для дерева и таблицы: `selectedId` и набор раскрытых узлов. Провайдер монтируется, когда есть данные; начальный набор раскрытых — корни (`getDefaultExpandedIds`). Состояние переживает фоновые рефетчи, фильтр и переключение представлений.

- Клик по узлу дерева → `select(id)`.
- Клик по строке таблицы → `useRevealNode`: раскрыть всех предков (`getAncestorIds`) и выбрать узел.
- Выбранные узел и строка прокручиваются в видимую область (`block: 'nearest'`), плавно — только без `prefers-reduced-motion`.

## Таблица

`OrgTable` держит локальное состояние фильтра и сортировки. `useTableRows` — три `useMemo`: `toTableRows(model)` → `filterRows` → `sortRows` (подробно — в [data-model.md](data-model.md)). Сортировка — чистая функция `getNextSort(prev, key, trigger)`, где `trigger` — `click` или `reverse` (двойной клик или активация с клавиатуры, у которой `event.detail === 0`). Строки — `React.memo`.

## Раскладка

Split-view сделан на CSS: `SplitView` всегда рендерит обе панели, а медиазапрос `width < 1280px` скрывает неактивную по атрибуту `data-view`. JS-подписки на размер окна нет, обе панели остаются смонтированными, поэтому их состояние и прокрутка не теряются.

## Mock-сервер

`server/index.ts` — `node:http` без фреймворка, исполняется Node 24 напрямую. `GET /api/org-tree` отдаёт 52 узла (4 дивизиона × 3 отдела × 3 команды), сгенерированных детерминированно (seeded PRNG), с `ETag` = версия данных, `Cache-Control: no-cache` и 304 на совпавший `If-None-Match`. Переменная `MOCK_SCENARIO` воспроизводит состояния клиента; клиент о ней не знает.

В dev Vite проксирует `/api` и `/ws` на сервер, поэтому клиент ходит на относительные пути и не требует переменных окружения.

## Стили

styled-components. Токены — CSS-переменные в `createGlobalStyle` (светлая и тёмная тема по `prefers-color-scheme`), `theme` ссылается на них. Динамические пропсы — transient (`$tone`, `$expanded`) с конечным набором значений. Inline-стили не используются.

## Live-обновления

```
server ticker ──patch──▶ /ws ──▶ useOrgLiveUpdates
                                   │ zod: liveMessageSchema
                                   ▼
                          resolveLiveMessage(model, message)
                     ignore │    apply │            │ refetch
                            ▼          ▼            ▼
                          ничего   setQueryData   invalidateQueries
                                   (applyPatch)   (cancelRefetch: false)
                                        │
                                        ▼
                     кэш → дерево и таблица перерисовывают только изменённое
```

- `useOrgLiveUpdates` вызывается в `DashboardPage`, держит один сокет и возвращает состояние соединения для шапки. Контекст не нужен: статус нужен только шапке.
- Переподключение: `getBackoffDelay` (экспонента с jitter, потолок 30 с), немедленная попытка по `online`, статус «офлайн» по `offline`. В cleanup эффекта ставится флаг `isDisposed`, а первое подключение отложено на тик, поэтому двойной монтаж StrictMode не создаёт второго соединения.
- Подсветка: `FlashValue` хранит предыдущее значение и номер поколения; реальное изменение увеличивает поколение, новый `key` перемонтирует `span` и перезапускает CSS-анимацию. Таймеров нет.
- Перерисовки: `applyPatch` сохраняет ссылки незатронутых узлов, `OrgTableRow` сравнивает поля строки, `useRevealNode` отдаёт стабильный колбэк. Патч перерисовывает только строки изменённого узла и его предков.
- Клавиатура в таблице: `useRovingRows` — одна tab-остановка, активная строка хранится по id, фокус переставляется только после нажатия клавиши.
- Дерево: ветки анимируются через `Collapsible` (см. [ADR-004](adr/004-height-animation-grid.md)).

Контракт сообщений и правила применения — в [data-model.md](data-model.md), выбор транспорта — в [ADR-003](adr/003-websocket-live-updates.md).
