# ADR-002. Агрегаты считаются один раз и живут в кэше вместе с моделью

## Контекст

Дерево и таблица показывают суммарные показатели по поддереву (численность, бюджет, средняя эффективность, взвешенная по численности). ТЗ требует считать агрегацию один раз после загрузки и мемоизировать, а на этапе live-обновлений пересчитывать только затронутый узел и его предков.

## Решение

Агрегаты — часть `OrgModel`: `aggregates[id] = { totalHeadcount, totalBudget, perfWeightedSum, avgPerformance }`. Они вычисляются в `buildOrgModel` сразу после валидации, то есть внутри `queryFn`, и кладутся в кэш TanStack Query вместе с узлами. Взвешенная сумма `perfWeightedSum` хранится отдельно, чтобы агрегат предка можно было пересобрать из агрегатов прямых детей без обхода поддерева. При нулевой суммарной численности средняя эффективность — `null` («—» в UI).

## Альтернативы

- **`useMemo` от сырого массива в компоненте.** Просто, но каждое изменение данных (в том числе один патч) пересчитывает всё дерево, а мемоизация привязана к жизни компонента, а не к данным.
- **Агрегаты только для таблицы, дерево показывает собственные значения.** Отвергнуто после первого прогона: «дивизион — 5 чел.» над командой из 15 читается как ошибка в данных.
- **Дельты при патче (`total += new − old`).** Дешевле, но накапливает погрешность на float; пересборка из детей стоит O(ширина × глубина) и точна.

## Последствия

- Компоненты получают готовые числа; сортировка и фильтр не трогают агрегацию.
- Патч (этап 03) обновляет узел и цепочку предков, создавая новые объекты только для них; остальные ссылки сохраняются, мемоизированные строки не перерисовываются.
- Агрегация — чистая функция с unit-тестами (`aggregate.test.ts`).
