# ADR-003. WebSocket для live-обновлений и сверка по версии

## Контекст

Этап 03 требует обновлений в реальном времени без полного рефетча, индикатора соединения и экспоненциального backoff при обрыве. ТЗ разрешает WebSocket, SSE или эффективный поллинг, а список документов прямо называет «контракт WebSocket-патча». Во время обрыва клиент неизбежно пропускает изменения, и после восстановления данные надо синхронизировать, не делая лишних запросов.

## Решение

WebSocket на `/ws` рядом с REST на том же `http.Server` (`ws`, режим `noServer`). Сервер держит одну монотонную версию данных: она растёт на 1 с каждым патчем и совпадает с `ETag` снапшота. Первое сообщение после подключения — `hello` с текущей версией. Клиент применяет патч версии `model.version + 1` прямо в кэш TanStack Query, а при пропуске версии, неизвестном узле или `hello` с другой версией делает один рефетч снапшота. Решение принимает чистая функция `resolveLiveMessage`, покрытая тестами.

## Альтернативы

- **SSE.** Проще на сервере и сам переподключается, но односторонний и не соответствует названию контракта в ТЗ; пришлось бы объяснять отклонение, а выигрыша на этом объёме нет.
- **Поллинг с `ETag`.** Работает через любой прокси, но даже 304-ответы — это запрос каждые N секунд и задержка до N секунд; противоречит «минимизации лишних запросов».
- **Безусловный рефетч после каждого переподключения.** Проще, но короткий обрыв без изменений тоже стоил бы полного снапшота. Сверка по версии из `hello` делает запрос только при реальном расхождении и заодно закрывает перезапуск сервера, у которого версия начинается заново.
- **Буфер пропущенных патчей на сервере.** Дал бы доставку без рефетча, но это состояние на клиента и логика очистки; снапшот из 52 узлов дешевле.

## Последствия

- Патчи не создают сетевых запросов; при стабильном соединении дашборд не обращается к REST вовсе, кроме ревалидации по stale time.
- Доставка не гарантирована, но корректность восстанавливается одним снапшотом; повтор патча безопасен.
- Nginx на этапе 04 должен проксировать `Upgrade`-заголовки для `/ws`.
- В сценариях mock-сервера, которые подменяют данные (`empty`, `error`, `invalid`), тикер не запускается, иначе патчи указывали бы на узлы, которых у клиента нет.
